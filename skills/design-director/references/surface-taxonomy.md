# Surface taxonomy

Classify the dominant work before choosing composition. A page may mix patterns, but one should dominate each major region.

## Monitor
Goal: understand state, priority, change, recency.
Useful shapes: status boards, alerts, timelines, feeds, threshold charts, compact metrics.
Design bias: hierarchy by urgency and freshness, not by decorative card equality.

## Operate
Goal: act directly on objects and get immediate feedback.
Useful shapes: command bars, canvases, inspectors, side panels, shortcuts, direct manipulation.
Design bias: actions close to objects; feedback and undo close to actions.

## Compare
Goal: judge many things against common criteria.
Useful shapes: tables, matrices, split views, ranked lists, stable scanning lanes.
Design bias: alignment, sorting/filtering, persistent context, comparable units.

## Configure
Goal: make choices, understand dependencies, preview consequences, commit safely.
Useful shapes: grouped forms, summaries, previews, staged commit regions.
Design bias: consequence-aware grouping and visible save/validation state.

## Learn
Goal: orient, read, progress, understand.
Useful shapes: article flow, walkthroughs, progressive sections, examples, progress markers.
Design bias: readable measure, pacing, orientation, return paths.

## Decide
Goal: build confidence and lead to a meaningful next action.
Useful shapes: focused claim, proof trail, comparison, risk reduction, dominant CTA.
Design bias: attention narrows as confidence increases.

## Explore
Goal: search, browse, filter, discover, backtrack.
Useful shapes: search, facets, maps, galleries, clusters, result lists.
Design bias: reversible movement; active filters/context never become mysterious.

## Mixed surfaces

Examples:
- analytics dashboard: Monitor + Compare;
- editor: Operate + Configure;
- pricing page: Decide + Compare;
- marketplace: Explore + Decide.

Name the primary pattern and use the secondary one only where the task requires it.
