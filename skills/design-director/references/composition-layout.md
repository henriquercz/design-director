# Composition and layout

Layout is the visible organization of work, evidence, hierarchy, and movement.

## Start with the work pattern

Use the surface taxonomy before choosing a layout family. The composition should make the primary job cheap.

## Focal point

Choose where attention should land first and why. Secondary and tertiary material must support that priority rather than compete equally.

Run a squint/blur test: the top priorities should remain visually legible when details disappear.

## Domain artifact first

Use the concrete artifact from the user's world as a compositional anchor when possible: route, schedule, contract, chart, workspace, receipt, room, product, match, queue, etc.

## Cards are a tool, not a default

Use cards when content is genuinely discrete, self-contained, and independently scannable. Prefer spacing, alignment, type, dividers, and shared surfaces when content belongs together. Avoid nested cards unless the nesting communicates real containment/state.

## Rhythm

Use a coherent spacing scale with a few tiers:
- micro spacing inside controls;
- component/content spacing;
- section/layout spacing.

The exact scale belongs to the project. Do **not** force every value into a universal 1/4/9 formula.

## Depth planes

Think in functional planes:
- canvas/background;
- content/work surface;
- attention/overlay layer.

Interactive elements should not be buried in decorative background layers. Overlays should visually and behaviorally relate to their triggers.

## Balance and intentional tension

Judge visual mass qualitatively through size, contrast, density, position, whitespace, and motion. Use counterweight when needed, but do not rely on pseudo-precise balance scores.

## Section continuity

For narrative/brand pages, visual continuation into the next section can encourage flow, but it is optional. Do not force a fixed number of pixels or fake a cliffhanger when the content benefits from a clean boundary.

## Wrappers

Every wrapper should have a job: width control, grouping, background, scrolling, positioning, or semantics. Remove shells that create dead margins or unnecessary cards.

## Relayout completion

A relayout must visibly change structure, such as:
- focal point;
- section order;
- text/proof relationship;
- primary action placement;
- navigation/sidebar/toolbar arrangement;
- grid/table/split/stack/flow model;
- responsive ordering or progressive disclosure.

Spacing can support structural change, not substitute for it.

## Container awareness

Prefer components that adapt to their available space, not only global viewport breakpoints. Use container queries when they materially simplify reusable layout behavior and browser support fits the project.
